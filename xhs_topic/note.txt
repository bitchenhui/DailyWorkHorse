Agent 真能接手音视频排障吗？

最近看到一个能逆向分析应用和原生二进制的 Agent 项目，我就顺手想：音视频排障里，那些日志、码流和复现步骤，能不能交给它先做？

我开始把 Agent 放进音视频排障流程：它真能接手哪一步？

01｜先让它整理现场
最稳的第一步，不是让 Agent 猜卡顿原因，而是让它把日志、时间线、编码参数和异常样本整理成结构化现场。像 RTSP 推流抖动这类问题，信息一多，人工翻日志很容易漏掉前后关系。

02｜让它提出验证方案
Agent 可以根据码流、QoS 指标和日志提出排查顺序，比如先区分采集、网络、编码还是播放端。但每一步都要能观测、能回滚，不能让它看到“延迟高”就直接改参数，更不能把推测写成结论。

03｜复现结果必须独立确认
如果 Agent 自动跑验证，关键不是它说“问题已修复”，而是修复后的指标和对照样本能否重复成立。独立确认这一步最好交给脚本、测试环境或人，避免同一个 Agent 既提方案又给自己盖章。

04｜权限要按环节拆开
我更愿意把权限分成读日志、跑测试、改配置三层：先读，再小范围验证，最后才允许变更。涉及生产链路时，默认只给只读权限。这样即使判断错了，也不会把一次排障变成一次事故。
