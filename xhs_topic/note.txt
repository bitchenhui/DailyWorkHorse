给 Agent 配一台电脑

现在不少编码 Agent 能自己开浏览器、读文件、调工具，听起来离“独立同事”只差一步。但团队真正敢放手的前提，往往不是它更聪明，而是每一步都能解释。

把编码 Agent 升级成“有记录的实习生”，团队才敢真的用它干活

01｜先看记录，再看结果
让 Agent 打开一个仓库、改几处代码不算难，难的是团队事后知道它为什么这么改。可以要求它先展示计划，再执行操作，并保留关键命令、文件变更和验证结果。这样出问题时，复盘的是流程，不是猜谜。

02｜权限要比能力更保守
Agent 有浏览器、文件系统和工具调用能力，并不等于应该一次拿到所有权限。先让它只读，再允许在临时目录写入，最后才开放真实环境。尤其是会发请求、改配置或删除文件的动作，最好加确认步骤。能回滚，比跑得快更重要。

03｜结果必须能被验证
“代码写完了”只是过程描述，不是完成标准。可以让 Agent 配套跑测试、静态检查或最小复现，并把命令与输出一起留下。涉及音视频这类对指标敏感的任务，还可以把延迟、清晰度和资源占用纳入验收，避免凭感觉宣布成功。

04｜把经验写成可复用技能
如果团队每次都要重新教 Agent 怎么查日志、定位问题、提交改动，不如把这些步骤整理成固定技能：输入是什么、先看哪些文件、允许执行什么命令、交付格式是什么。成熟的做法不是每次靠临场提示，而是把团队习惯变成可重复执行的流程。
